# 上下文压缩与发送前预算检查

## 两类消息

当前 Agent 主流程中，`AIClient._history` 只追加已完成轮次的用户输入与最终回复，
压缩后也包含一条历史摘要。`Agent.run()` 的本轮 `messages` 则包含当前输入、工具调用与结果。
工具轨迹仍不写入持久历史 JSON。

发送给模型的完整请求是：系统提示 + 持久历史 + 本轮消息 + 工具 Schema。
长期记忆会注入本轮用户消息，因此也占用输入预算。
长期记忆默认取消条数淘汰，但注入内容有单独长度上限；同一事实更新、过期与无效记录清理见
[长期记忆管理](MEMORY_MANAGEMENT.md)。

## 预算

启用压缩时，每次普通或流式调用在发送前检查估算 Token 数。

```text
输入预算 = floor((context_window - max_tokens - safety_margin) × trigger_ratio)
```

预算扣除了实际生成上限和安全余量。输出预留不得小于 `AIClient.max_tokens`；
修改实际生成上限后需要重新配置压缩器。
当前使用 CJK/字符混合估算，并非具体模型的官方 tokenizer，因此预算检查保证的是
“估算不超限”，不代表对所有模型的实际 Token 数都有精确保证。

服务模式与 Demo 都使用下面的配置：

```yaml
providers:
  # 在既有 Provider 配置中加入/调整这一项
  - context_window: 32768
agent:
  max_tokens: 4096
  enable_context_compression: true
  compression_trigger_ratio: 0.85
  compression_safety_margin: 1024
  compression_keep_recent: 6
```

这是要合并到现有配置的片段；不要用它覆盖已有 Provider 名称、连接信息和凭据。
`keep_recent` 必须大于零，触发比例在 `(0, 1]` 内，窗口必须容得下输出预留与安全余量。
关闭 `enable_context_compression` 后，此压缩及预算检查流程不启用。

## 超预算后的处理顺序

1. 先检查当前用户输入、系统提示和工具定义是否已经超过预算；这种情况直接报错，
   不截断用户要求，也不发起无效的摘要请求。
2. 对历史按完整用户轮次进行摘要，优先保留最近 N 条消息；边界回退到用户消息开始处。
   预算不足时逐步减少保留数量，最后可把已完成的历史全部改为摘要。
3. 对本轮较早的完整工具调用组进行摘要，保留本轮最初用户输入以及最新工具组。
   摘要输入包含工具名称、参数、调用 ID 和结果，不再只拼接消息正文。
4. 若最新工具结果本身过大，保留其开头与结尾，中间加入明确截断标记。
   不修改工具调用参数、名称、ID 或用户输入。完整内容应通过工具再次分段读取。
5. 再次检查完整请求。只有估算长度在预算内且工具配对合法，才提交压缩后的历史和本轮消息。

仍超预算时抛出 `ContextBudgetExceededError`，不调用主任务模型，也不提交临时压缩结果。
错误包含处理后的估算长度、预算以及失败原因。调用方可以提示用户拆分输入或调整配置。
摘要模型仍可能已经被调用并产生费用；预算失败不会撤销已发出的摘要请求。

## 消息边界

持久历史从新一轮用户消息开始保留，避免只留下助手回复而丢掉对应问题。
本轮轨迹则按 `assistant(tool_calls) → tool(results)` 完整组保留。
发送前校验每组结果 ID：空/重复的调用 ID、未知/重复的结果 ID，以及缺少结果的调用组
会抛出 `ContextProtocolError`。同时支持一个调用组有多个工具结果，以及组跨越历史与本轮列表。

这些检查保证消息结构，不保证模型生成的摘要完全保留旧对话的所有事实。
本轮用户输入通过原文固定保留；历史摘要的语义质量仍需真实任务评测。

## 摘要失败与资源控制

摘要请求本身也计算输入与输出预算。较大的历史分块处理，上一块摘要加入下一块请求。
每次主请求准备最多调用摘要模型 8 次，每次摘要超时为 30 秒。
空白、过长或失败的摘要不会替换历史；比原文更长的压缩结果也不会采用。

所有处理先在临时列表上进行，准备失败或取消时保留原 `_history` 和调用方消息，并恢复
原摘要状态。摘要失败后若原历史加缩短的工具结果仍能满足预算，可以继续发送合法请求。

成功后保存到会话 JSON 的仍然是压缩后的历史。历史与 KV 使用原子 JSON 文件替换，
不构成联合事务或原始消息归档。执行中任务另由 [Checkpoint](CHECKPOINTS.md) 保存轮次、
工具结果与上下文，支持显式恢复；上下文压缩本身不提供任务恢复。

## 验证

```powershell
python -m pytest tests/test_context.py tests/test_context_budget.py -q
```

测试覆盖整轮切割、多个工具结果配对、摘要分块、失败/取消回滚、工具输出首尾保留、
不可压缩输入的发送阻断、普通/流式共用预算检查，以及真实 Agent 主循环的历史保存规则。
模型调用使用可记录请求的 Fake Provider，验证长度与协议；摘要语义质量需另外评测。

## 对照与执行记录

`agent.context_strategy` 默认 `summary`；设为 `truncate` 时按完整轮次/工具组丢弃旧内容，保留本轮用户输入并共用预算与协议检查。
这一模式是评测基线，可能丢失早期约束。压缩调用、前后估算长度、失败/阻断会进入任务 trace。对照命令见 [任务评测](EVALUATION.md)。
