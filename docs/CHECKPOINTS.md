# 文件原子写入与任务 Checkpoint

普通编码任务现在支持持久化轮次、恢复工具执行和中断后的继续执行。
这与只恢复已完成的对话历史不同，也与任务工作区的文件副本不同。

## 开启与使用

服务和 Demo 默认开启，SDK 按需开启。配置：

```yaml
agent:
  checkpoint_dir: .xclaw/checkpoints
```

设置为 `null` 可关闭。checkpoint 目录相对进程启动目录解析，服务重启时应保持一致，
也可以配置绝对路径。默认不删除旧 checkpoint。

启动 Demo：

```powershell
uv run xclaw --config config.yaml --demo
```

Demo 和飞书/QQ 支持：

```text
/checkpoints                 # 当前会话/项目最近 20 个 checkpoint
/resume <checkpoint-id>      # 显式恢复指定任务
```

任务异常时会返回 checkpoint ID。进程被强制结束时可能来不及返回 ID，重启后可用
`/checkpoints` 查找。服务不会自动重新执行重启前的任务；恢复需要显式指定 ID。
IM 会校验原会话与原项目，不允许通过另一个会话恢复任务。
`/reset` 清除会话记忆，不删除历史 checkpoint；显式恢复旧任务会恢复当时的历史和记忆。

启用 `isolate_workspace` 时恢复原来的 `work/` 副本，不新建副本，不自动回写原项目。
恢复成功后可以重新导出 diff，原有冲突检查与显式回写流程不变。

SDK 示例：

```python
agent = CodingAgent(
    provider,
    workspace_dir="E:/repo",
    checkpoint_dir="E:/state/checkpoints",
)
try:
    reply = await agent.run("修复问题并运行测试")
finally:
    print(agent.last_checkpoint_id)

# 使用相同项目、模型、提示词、工具及执行配置创建新 Agent 后：
reply = await agent.resume(checkpoint_id)
```

## 持久化边界

每个任务一个带版本号的 JSON，使用同目录临时文件、flush/fsync、原子替换保存。
OS 文件锁防止多个执行器同时恢复同一个任务；进程退出后锁自动释放，锁文件可以保留。

保存内容包括：

- 原任务输入、会话/项目标识、工作区和工具白名单。
- 已消耗轮次、当前阶段、最新最终输出或被完成校验器拒绝的回复。
- 完整当前工具消息链、已保存历史、上下文摘要、长期记忆和模型用量计数。
- 本轮经过校验的调度计划、已开始调用 ID、每个已完成或跳过调用的结果，以及待交付附件路径。

模型调用前后的上下文、生成工具调用之后、每个工具开始前和完成后、整轮结束以及最终
完成时均保存状态。模型网络请求中断时，恢复后重新请求该轮模型，不重新执行先前已落盘的工具。
恢复沿用原轮次预算，不把轮次计数归零。完成的任务再次恢复直接返回缓存结果。
恢复时检查工作区、模型/提示词、工具声明、执行策略、轮次预算和部分上下文配置。
有完成校验器的任务恢复时仍必须提供校验器；不能通过恢复绕过原验收要求。

Checkpoint 包含原始任务、代码片段、工具输出和记忆，属于本地运行数据，不应提交到源码仓库。
它不保存 API 密钥配置，但任务或工具输出本身可能含敏感内容。

## 工具执行中断

| 中断时状态 | 恢复行为 |
|---|---|
| 工具尚未开始 | 按保存的计划执行 |
| 工具结果已落盘 | 复用结果，不重复执行；失败仍阻断依赖调用 |
| 工具开始但无持久化结果，可信工具明确声明可并发的纯读取/提示词调用 | 允许重新执行 |
| 工具开始但无持久化结果，写入、Bash、Git、MCP 或其他未知副作用工具 | 暂停恢复，报告调用 ID，不自动重放 |

开始标记只能表示“可能执行过”，不能证明副作用已经发生或已经完成。
例如 Git 提交成功后、保存结果前进程死亡，不能通过重新提交来猜测状态。
普通工具异常仍返回给主模型进行处理，不会因为开启 checkpoint 而自动反复重试。

对不确定调用，先检查文件、Git 日志、容器进程或外部服务状态，再通过 SDK 提供实际结果：

```python
reply = await agent.resume(
    checkpoint_id,
    resolutions={
        "call_123": "已核对：目标文件内容完整，写入完成",
        # 若确认失败，使用现有失败约定，例如：
        # "call_123": "错误: 写入未完成，目标文件仍是旧版本",
    },
)
```

提供成功结果会允许依赖调用继续；提供失败结果会使其跳过。调用 ID 必须是当前结果
不确定的调用。该接口不会重新执行已核对的工具；需要修复时由后续模型重新发起调用。
IM/Demo 的 `/resume` 不接受任意覆盖结果，遇到此情况会明确暂停，使用 SDK 核对后恢复。

文件附件恢复会从已记录的成功 `deliver_file` 调用重建本地交付队列，并重新检查路径和文件。
平台上传/发送发生在 Agent 任务之后，不包含在 checkpoint 的事务中；恢复已完成任务可能
再次发送回复或附件。不能据此声称外部交付“恰好一次”。

## 原子文件写入的范围

内置 `write_file` 和 `edit_file` 使用原子替换，并保留已有文件的权限位。
替换前发生失败，目标保持旧版本；替换成功后是完整新版本，避免直接清空后只写入一半。
正常失败会清理临时文件，强制退出可能留下同目录的 `.tmp` 文件。

原子替换只保护单个文件。它不提供多文件事务，也不保证所有文件系统或断电场景下的物理持久性。
任务副本回写仍有原有的多文件部分完成边界。通过 Bash、第三方 Skill 或 MCP 自行写文件，
不自动获得内置文件工具的原子写入保证。

Checkpoint 不回滚文件、不终止远程遗留进程、不保存完整文件系统快照，也不保证副作用
恰好执行一次。恢复期间应保持工作区和外部执行环境稳定；它不检测所有外部代码修改。
模型供应商可能重新计费中断后重发的请求，用量计数也不等同于精确账单。
当前仅覆盖 `Agent.run` / `resume` 的循环，不恢复 `run_with_plan` 的内存规划器或消息队列。

## 验证

```powershell
uv run pytest tests/test_checkpoint.py -q
```

覆盖原子替换故障、进程强制退出、网络中断后恢复、工具结果去重、依赖失败跳过、
不确定副作用拦截与核对、只读调用重试、状态写入失败、配置/会话校验和独立任务副本恢复。
