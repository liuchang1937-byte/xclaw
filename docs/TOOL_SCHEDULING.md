# 工具并行与依赖调度

普通 Agent、飞书服务和 Demo 默认启用 LLM 调度。同一轮只有一个工具时直接执行；
多个工具时使用相同 Provider / 模型发起一次独立的调度请求，不调用工具、不写入主对话历史。
调度输入包括当前批次的调用 ID、说明、参数、代码侧的并行声明和最近四条消息的节选。

## 执行流程

1. 主模型返回标准 `tool_calls`。
2. 调度模型输出 `serial`、`parallel` 或 `dag`，并列出 `depends_on`。
3. 校验调用 ID 完整且唯一、依赖存在、没有自依赖或循环，不允许计划修改工具参数。
4. 对文件交付追加固定前置规则：同一路径的写入和检查在交付前完成；写入路径不明时保守等待。
5. 按依赖拓扑分批执行。只有明确声明安全、能力限于 `file_read / prompt` 的工具可以并发。
6. 工具失败时跳过依赖它的调用，独立调用继续；全部结果按原始 `tool_calls` 顺序回填。

计划不是权限授权。原有路径、能力和执行后端检查始终执行。
模型超时、服务异常、返回无效 JSON、缺失调用或循环依赖时退回串行；文件交付的固定规则仍生效。

例如两次独立读取可以并行；创建 Excel → 检查 → 交付按依赖执行。
如果下一步的参数必须根据前置结果确定，调度模型可标记 `defer: true`，本轮不执行该调用，
返回明确提示，由主模型下一轮使用真实结果重新构造参数。不会把结果自动插入猜测的参数或占位符。

## 配置

本地 `config.yaml` 的 `agent` 下可添加：

```yaml
agent:
  tool_scheduling:
    enabled: true
    max_parallel: 4
    planning_timeout: 10
```

`max_parallel` 范围 1～16，`planning_timeout` 单位秒、范围大于 0 且不超过 60。
`enabled: false` 关闭额外模型请求，使用保守串行调度。配置有默认值，不必修改现有凭据。
多个工具的批次会多一次模型请求，其 token 用量计入 Agent 客户端累计统计。
输入过大或估算超过已配置的上下文预算时也退回串行，规划不会无限重试。

## 工具与执行路由

注册可信的无副作用工具时明确声明：

```python
Tool(
    name="query",
    description="读取数据",
    func=query,
    capabilities=frozenset({Capability.FILE_READ}),
    parallel_safe=True,
)
```

`parallel_safe` 默认关闭。仅设置该标记不能让写入、删除、进程或 MCP 工具并行。
内置文件读取、目录列表、文件搜索、Excel 检查、提示词 Skill 和参考资料读取已声明可并行。
文件交付会修改本轮附件队列，仍然独占执行；MCP 的外部副作用未知，默认独占执行。

路由使用读写执行门：安全读取共享，其他操作独占，不与读取重叠。
同步安全工具交给线程池；内置文件读取和搜索也将阻塞 I/O 移到线程池，并保留 ContextVar 路径策略。
取消后台读取时，等待线程真正退出后再释放执行门，避免读取尚未结束就启动独占操作。

## 当前边界

- 调度依据本轮可见的参数、说明和节选上下文，不是完整的程序数据流分析；模型仍可能漏判语义依赖。
- 依赖失败识别兼容现有工具错误约定：`❌`、`错误:`、`工具 … 执行失败:` 以及进程 `exit_code`。
  自定义工具应抛出异常或使用明确错误前缀，不能仅返回一段普通文字表示失败。
- 写入不同文件也保守串行；没有按文件资源分配细粒度锁，也没有开放 MCP 只读提示的并发授权。
- `run_with_plan()` 是另外的显式计划入口，仍按声明的依赖逐步串行执行。
- 执行门属于单个 Agent，不是跨会话的工作区锁；当前多个用户仍共享配置的文件工作区。
- 不针对 CPU 密集计算提供多进程加速。并发收益主要来自独立 I/O 等待的重叠。
