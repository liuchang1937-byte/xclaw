# 串行工具调用与依赖图调度对照（2026-10-30）

本次是单独的调度消融实验。两组都使用摘要上下文管理，只改变工具调度开关；日常评测默认仍只运行最终方案 `summary_scheduled`。

## 实验设计

分两层测量，避免把模型随机性或模拟等待误认为实际业务收益。

| 层次 | 固定条件 | 场景与次数 | 判定 |
|---|---|---|---|
| 同调用序列受控测试 | 同工具、参数、初始顺序与固定数据；串行关闭调度，DAG 使用真实模型规划，最大并发 4 | 7 个场景 × 3 次 × 2 组，共 42 次 | 实际工具函数开始/结束时间、依赖先后、写入互斥、失败阻断、结果顺序与并发上限 |
| 完整 Coding Agent | 同任务、模型、预算、摘要策略、初始文件与 Docker 镜像；每次独立工作区；任务间并发 1；交替两组执行顺序 | invoice、currency、authentication、geometry，各 3 次 × 2 组，共 24 次 | 独立 Docker 隐藏验收、文件修改约束；保留失败，全部尝试计入成本 |

受控测试的工具等待使用 `asyncio.sleep` 模拟 I/O，规划是真实 API 调用；它只说明调度执行机制与开销，不代表生产流量吞吐。完整 Agent 使用真实文件工具和模型调用，但任务是小型合成代码修复，不代表大型真实仓库。

完整 Agent 固定模型 `deepseek-v4-pro`，temperature=0，上下文 8192，单次输出预算 2048，最多 12 轮，任务超时 180 秒，规划超时 10 秒。受控层没有主模型生成，使用相同模型的真实调度请求与固定工具调用。temperature=0 不保证远端服务响应完全确定。两组的 token 和延迟均包含各自实际的辅助调用、重试与失败，不扣除 DAG 规划成本。

Docker 镜像固定为 `sha256:4a79da4b92e5fd1d93e2651fb5c72eebc38b57a79ab159e04d9faca968bd0e19`。完整环境、依赖包与源码哈希记录在各运行目录的 `experiment.json` 中。

## 同调用序列结果

下表均为每组 3 次平均值，净加速比 = 串行总耗时 / DAG 总耗时，大于 1 表示 DAG 更快；DAG 总耗时已包含规划。

| 场景 | 串行秒 | DAG 秒 | DAG 规划秒 | 净加速比 |
|---|---:|---:|---:|---:|
| 单次快速读取 | 0.058 | 0.061 | 0（已有单工具直通） | 0.95× |
| 4 次独立快速读取（每项 50ms） | 0.244 | 1.577 | 1.517 | 0.15× |
| 4 次独立慢读取（每项 2s） | 8.032 | 3.109 | 1.089 | 2.58× |
| 8 次独立慢读取（每项 2s） | 16.066 | 5.531 | 1.502 | 2.90× |
| 两个独立前置汇合后检查（各 1s） | 3.025 | 3.330 | 1.311 | 0.91× |
| 读取 → 写入 → 读取（各 0.5s） | 1.566 | 3.216 | 1.681 | 0.49× |

正常场景两组均通过 18/18；DAG 最大实际并发为 4，依赖先后、写入互斥和结果顺序检查均通过。18 次真实规划共消耗 10,968 token，无规划降级。不能将这层的规划 token 与完整 Agent 的总 token 直接比较。

故障场景另计：前置查询故意失败，独立查询必须继续，依赖它的检查禁止执行。DAG 正确处理 3/3，跳过 3 次后继；当前 `enabled=False` 串行实现继续执行后继，通过 0/3。这里测的是本项目两条执行路径的失败传播契约，不能推广为所有串行实现都不能阻断后继，也不能把这 3 次样例称为全面的异常恢复率。

按任务和运行编号配对，共 12 对，其中 10 对两组均成功，无单组独有成功。只看这 10 对，串行平均 **20.948s**、DAG **23.903s**，DAG 多 **2.955s / 14.11%**，净加速比 **0.876×**；排除失败也没有整体提速。

两组各失败 2 次，都发生在 currency 第 2、3 次：最终主模型响应 `finish_reason=length`，输出消耗完 2048 token，没有工具调用，没有文件修改，隐藏验收失败。观察到的直接失败环节是主模型输出截断，不能将其直接归因于依赖图错误。

耗时分解也支持优先优化规划：全部尝试的主模型请求时间，串行累计 257.469s、DAG 累计 254.990s；DAG 额外规划累计 **42.918s / 22,788 token**，平均每次规划 **1.788s**。在这个快速文件工具样本中，规划开销明显，而实际并行执行的收益不足；这些是观测分解，并非严格的跨请求因果归因。

保存轨迹的确定性评分已离线重放 24 次，未调用模型，也未重新执行隐藏验收；成功判定与原结果一致。

## 指标口径与边界

- 成功率按任务尝试统计，以隐藏验收和文件约束为准，不依赖模型自评。各任务重复次数相同，最终任务等权结果与尝试等权结果一致。
- 平均步数为主模型调用次数；模型总调用次数另外包含规划、摘要等辅助请求。工具调用次数是实际执行的调用数，跳过另计。
- Token 为服务端报告的输入加输出用量，包含规划；本次用 token 比较成本，没有估算货币费用。
- 完整 Agent 延迟沿用 runner 的 `duration_seconds`：从调用 `bot.run()` 前到返回或异常，包含模型、规划与工具执行，排除工作区准备、清理与独立隐藏验收；隐藏验收耗时另存为 `validation_seconds`。它不包含线上用户端网络传输。
- 每组完整任务只有 12 次，P95 标记为“样本不足20”；不将最大值当作稳定的 P95。受控层混合场景的 P95 也不能替代真实流量的尾延迟。
- 完整 Agent 的并发峰值取 trace 中调用的重叠区间；受控层进一步在实际工具函数内部记录开始/结束来验证实际重叠。
- 工具执行错误率不等于工具选择正确率；相同工具参数的重复可能是必要复查，不直接视为浪费。该样本未标注答案准确率、用户满意度或全部工具选择 Oracle，这些指标不编造数值。
- 这次只比较串行与 DAG 调度，不比较摘要和截断，不覆盖完整的对抗与长任务评测集。

## 可调优方向

1. **优先降低规划开销。** 快速读取批次节省的执行时间小于一次模型规划的时间。对于由代码明确声明依赖或独立关系的常见批次，可尝试直接执行确定性依赖图；未知语义关系仍交给模型规划。不能仅凭“只读”就认定独立，资格检查读前置缓存就是反例。单工具直通已经存在，无需重复实现。
2. **按可节省的等待时间选择策略。** 用真实工具耗时历史和依赖关键路径估算并发收益；对于不能并发的写入链，可使用有明确失败传播规则的保守执行策略，减少没有执行收益的模型调用，同时保留副作用顺序与失败阻断。
3. **修复输出截断的结束语义。** 对 `finish_reason=length` 且没有产出工具调用或答案的响应，应明确标记未完成，必要时在预算内继续或向用户说明，不应直接按正常结束处理。后续试验可单独比较输出预算/推理设置；本次对照不临时提高某组预算或补跑覆盖失败。
4. **以真实慢工具和业务任务扩展留出集。** 当前文件工具很快，MCP 工具默认独占，受控慢读取不能证明 MCP 已获得相同加速。新增只读工具并行能力之前需要确认能力声明、数据依赖及路由约束。用扩展任务验证收益，再用足够样本观察 P95 与关键任务回归。

这些是依据测量结果提出的后续优化，本次未修改生产调度策略。
