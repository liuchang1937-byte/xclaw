# XClaw 简历项目表述

## 推荐版本：Agent 开发方向

**XClaw｜可扩展 Coding Agent 运行框架**

**技术栈：** Python、asyncio、OpenAI SDK、JSON Schema、Docker、MCP、飞书 WebSocket。

**项目简介：** 面向本地代码仓库开发与飞书交互场景，从零实现 Coding Agent 框架，
打通需求接收、工具执行、代码修改与文件交付流程，支持长对话处理和会话恢复。

- **多工具执行：** 基于 asyncio 实现 ReAct 循环，由函数类型注解生成 JSON Schema 并校验
  调用参数；引入依赖图校验、独立只读调用并发和写入互斥，支持有先后约束的多工具任务，
  无效调度计划回退串行，前置调用失败时跳过后续依赖调用。
- **长上下文稳定性：** 针对长任务历史膨胀和工具消息错配，实现完整请求 Token 预算检查、
  按对话轮次与工具调用组压缩、超长结果截断及压缩失败回滚；在发送前拦截超预算请求与
  无效消息配对，保留本轮用户要求。
- **代码修改保护：** 建立 **view/edit/execute 3 级权限**与工作区路径校验，通过 Docker
  隔离命令执行；使用独立工作区承载修改，导出 diff 供审阅，回写前以文件哈希检测冲突，
  支持超时终止、任务取消及回写异常后的文件回滚。
- **能力扩展与交付：** 实现目录型 Skill 按需加载及 MCP 工具接入，落地 **Word、Excel
  2 类文档处理能力**；通过飞书 WebSocket、附件上传和文件交付检查，打通需求接收、
  文件生成到实际附件交付的流程。
- **会话与记忆维护：** 按会话串行处理消息，持久化历史和 KV 记忆，支持重启恢复；
  将长期记忆改为同一作用域、同一事实的新值替换旧值，解决新旧值重复注入问题，
  支持项目隔离、明确撤销和过期清理。
- **质量评审与验证：** 实现相关性、准确性、完整性和有用性 **4 维 LLM-as-Judge 评分**，
  校验输出格式与逐字证据引用，生成具体改进建议；建立 **260+ 项自动化回归用例**，
  覆盖工具协议、上下文边界、权限隔离、文件交付及记忆更新。

## 版面紧张时的精简版

**XClaw｜Python Coding Agent 框架**

- 基于 asyncio 实现 ReAct 执行循环、工具注册及 JSON Schema 参数校验，结合依赖图检查、
  只读并发与写入互斥，完成多工具任务执行流程。
- 实现完整请求预算检查、按对话轮次与工具组压缩、消息配对校验和失败回滚，
  在发送前拦截超预算请求及无效工具消息。
- 建立 **3 级执行权限**和独立任务工作区，支持 diff 审阅、回写冲突检测及异常回滚；
  接入 Skill、MCP 和飞书，支持 **Word/Excel 2 类文档**处理与附件交付。
- 实现会话恢复、项目记忆更新与过期清理，结合 **4 维模型评审**和
  **260+ 项自动化回归用例**验证执行、交付及记忆维护流程。

## 数据依据与表述边界

这版使用可核验的功能覆盖和工程验证数据，不将其包装为线上用户收益或效率提升。
正文不使用先前移除的合成任务规模、成功率差异及 Token 节省比例。

| 数据或产出 | 依据 | 面试时的解释 |
|---|---|---|
| 3 级权限 | 执行策略中的 view/edit/execute | 分别控制读取、编辑与命令执行权限 |
| 2 类文档处理 | `skills/word`、`skills/excel` 及相关回归 | 支持生成和处理文档，并通过飞书发送实际附件 |
| 4 维模型评分 | `src/xclaw/evaluation/judge.py` | 相关性、准确性、完整性、有用性；检查引用确实来自所提供证据 |
| 260+ 项自动化回归 | 本地 pytest 收集与执行结果 | 证明工程行为有自动化验证，不等于真实业务成功率 |
| 新旧记忆替换 | `tests/test_memory_lifecycle.py` | 同项目 Python 改 Java 后，旧值不再保留在该事实的有效记忆和提示中 |

2026-10-16 最新核验：记忆与会话专项 34 项通过；完整检查 263 项通过、2 项因符号链接权限跳过，
1 项真实容器测试因 Docker 引擎未启动失败。正文的“260+ 项用例”不表示本轮所有检查均通过，
详见 [本地验证记录](VALIDATION_20261016.md)。

四维评分已完成少量真实模型样本的链路验证，尚未人工标注，不能声称与人工达成某个一致率。
长期记忆的同义事实识别仍由模型判断，目前没有数据库与向量检索，不能写成已实现向量语义记忆。
哈希冲突检查是文件级拦截，不是自动合并；会话恢复也不等于自动续执行中断命令。

## STAR 面试讲述示例

以下展开用于面试准备，正式简历使用上面的短条目。

**上下文管理：** 长任务会积累对话和工具结果，可能超过模型窗口，直接截断又可能丢失要求。
负责实现发送前的预算与消息协议检查，按完整轮次、完整工具组处理历史，并设计失败回滚。
产出是可检查、可阻断的上下文准备流程，自动化用例验证用户输入保留、消息配对和失败后的状态完整性。

**记忆维护：** 用户将同一项目从 Python 改为 Java 时，旧实现仍把两条记录一同注入模型。
改为执行前维护当前事实、同键替换旧值，按项目区分作用域并校验更新所引用的用户原文。
用例验证更新后的有效存储、提示和重启恢复均使用新值，同时其他项目的记忆不被覆盖。

**文件交付：** 飞书对话中仅返回本地文件路径不能完成实际交付。
实现 Word/Excel Skill、附件上传和交付检查，把生成的文件作为实际附件返回，形成可使用的交付流程。
