# 长期记忆更新与清理

长期记忆默认没有条数上限，存储不再因超过 50 条而淘汰最旧记录。
`ConversationMemory(max_size=...)` 仍允许调用方主动设置容量；默认值为 `None`。

## 当前事实与作用域

一个作用域中的一个键只保留一个有效值。例如 `project_language` 从 Python 改为 Java，
旧值从有效列表中移除，保存后的 JSON 和后续记忆注入都只包含新值。
用户偏好使用会话内的共享作用域，项目要求使用工作区路径确定的项目作用域。
用户/群聊的记忆仍由各自会话分别保存。独立任务副本沿用原工作区的项目作用域，
临时副本路径不会让每次执行变成一个新项目；更新一个项目不会覆盖其他项目的同名键。

## 自动维护

开启 `agent.auto_memory` 时，在任务执行前，用本轮用户原文与当前作用域已有事实进行维护：

1. 模型输出 `upsert`（新增或替换）或 `forget`（撤销）。同义措辞应复用已有键。
2. 每项操作须引用本轮用户原文中的连续片段；程序检查操作类型、作用域、字段与引用。
3. 已有键沿用原作用域。删除只能指向本次提供给模型的已有事实，不能执行清空操作。
4. 模型失败、超预算、输出截断或引用不合规时不采用相应操作。当前用户明确要求优先于历史参考。

例如“项目以后改用 Java”应替换原语言要求；“项目也需要支持 Java”属于补充，不能直接删除 Python。
这种语义区别仍由模型判断，原文引用存在不能证明判断一定正确；尚未进行真实模型批量准确率实验。
助手自己的回复不作为自动事实更新的依据。任务执行失败时，已确认的用户要求仍保留；
服务的正常异常处理也会尝试持久化这些更改。

## 清理与兼容

- 同一作用域、同一键的旧值在更新时删除；旧 JSON 文件加载时也会合并重复键，保留最新记录。
- 无效结构、空键、不可序列化值和空事件不进入有效记忆；完全相同的事件去重。
- 可用 `expires_at`（Unix 时间戳）标注有效期；读取、保存和格式化时清理已过期记录。
- 可用 `forget(key, scope=...)` 明确撤销事实。不会仅因记录较旧就删除仍有效的事实。
- 旧文件中没有作用域的信息按原会话的共享记忆兼容读取；无法自动推断它原来属于哪个项目。
- 历史事件标记为历史参考，不能当成当前要求；不会仅凭一条新事实自动删除所有相关历史事件。

目前新值会替换旧值，没有额外保存完整的变更审计历史。

## 存储与模型输入分开限制

不限制存储条数不等于一次发送全部记忆。
记忆提示默认最多 6000 字符，超出时保留较新的可容纳条目，并显示省略标记；被省略的记录仍在存储中。
记忆维护候选集合也有长度与请求估算预算限制，超预算会放弃自动维护。
完整模型请求仍经过现有上下文预算检查。

这只是当前 JSON/KV 记忆的生命周期改造，尚未引入数据库、向量检索或全库语义冲突扫描。
大规模长期记忆需要进一步增加语义候选检索，才能稳定找到更早、使用不同表述保存的相关事实。

## 验证

```powershell
python -m pytest tests/test_memory.py tests/test_memory_extractor.py tests/test_memory_lifecycle.py tests/test_service_isolation.py -q
```

覆盖超过 50 条保存恢复、同键替换、跨项目隔离、过期和无效记录清理、伪造引用拒收、
提示长度限制，以及在本轮主请求之前更新记忆和任务失败后的状态保留。模型调用使用模拟提供方。
