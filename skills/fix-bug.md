# Bug 修复

## 执行流程

### 第 1 步：收集信息

向用户确认以下信息（如果用户没有提供）：
- 错误现象：报错信息、异常行为、复现步骤
- 相关文件：用户怀疑哪些文件有问题
- 最近变更：是否有最近的代码改动可能引入问题

### 第 2 步：定位根因

不要猜测！按以下步骤系统化排查：

1. 用 `read_file` 读取用户指定的相关文件
2. 用 `git_log` 查看最近的提交，寻找可能引入问题的变更
3. 用 `git_diff` 查看最近的未提交变更
4. 用 `search_in_files` 搜索错误信息中提到的函数名、变量名
5. 分析逻辑链路，找到根因（不是症状）

### 第 3 步：提出修复方案

在修改代码之前，向用户说明：
- 根本原因是什么
- 修复方案（改哪里、怎么改）
- 为什么这个方案是正确的
- 可能的副作用

### 第 4 步：实施修复

1. 用 `read_file` 再次确认要修改的文件当前内容
2. 用 `write_file` 写入修复后的代码（修改整个文件，不要只改一行）
3. 在修改处添加注释说明修复原因

### 第 5 步：验证

- 说明修复后应该如何验证（运行什么测试、检查什么行为）
- 如果有其他可能受影响的代码路径，指出来让用户注意
- 如果修复引入了任何行为变更，明确告知
